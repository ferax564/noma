# Noma Status and Gap Analysis: the Next Notion and Confluence for the Agentic Era

**Date:** 2026-09-25 · **Baseline:** v0.18.0 + unreleased work on `main` (`0e75361`) · **Branch:** `claude/laughing-faraday-93fchh`

This review asks three questions:

1. What does Noma ship today?
2. What was still missing for Noma to replace Notion and Confluence for teams that work with AI agents?
3. What did this pass build, how is it tested, and what is left?

It builds on `docs/review-2026-09.md` (Confluence parity, security) and `docs/strategy-2026-09.md` (format decision, competitor research). Both docs have been updated with the items closed here.

---

## 1. Verdict

Noma's thesis is unchanged, and the core it rests on is solid. Pages are plain-text `.noma` with stable block IDs. Agents propose block-level patches that must pass proof, human approval, and a hash-checked apply. Notion and Confluence both added agents, MCP, and presentation modes in 2026, but in both products agents write whole pages. Neither can give an agent a stable, reviewable, per-block address.

Before this pass, the product around that core had a few deal-breaking gaps:

- **Notion migration.** Only Confluence import existed.
- **Agents in the team.** People could not hand work to an agent the way Notion 3.6 "External Agents" and Rovo @-mentionable agents allow.
- **Semantic search.** It used a 96-dimension hash vector, not a real embedding model.
- **Identity.** Login worked only through a trusted proxy header.
- **Storage.** Attachments used local disk only, and Confluence import dropped attachments.
- **UI coverage.** Some features were available only through the API.

**This pass closes all of them.** The remaining gaps (§5) are about scale and depth, such as multi-node collaboration, native SAML, and same-block merges. None of them contradicts the product's positioning.

## 3. Against Notion and Confluence (September 2026)

| Capability | Notion 3.x | Confluence + Rovo | Noma |
|---|---|---|---|
| Hand work to an agent in the flow of work | External Agents, @-mention, board tasks | Rovo agents, @-mention | **@-mention or task-assign an agent.** It replies in the thread and opens *proofed* proposals |
| What an agent's edit is | Page-level write | Page-level write | Block-level patch with proof, independent approval, and `baseHash` |
| Stable, human-readable block address | Opaque UUIDs | Storage XML, page versions | `{#id}` / heading slug as public API |
| Git-diffable source | Export only | Export only | Plain `.noma`, two-way Git sync |
| Per-claim citations | ❌ | ❌ | `[doc:block@hash]`, validated before an answer is shown |
| Semantic search | Proprietary | Rovo search | Hybrid lexical + real embeddings (pluggable, policy-gated) + trust/freshness |
| Migration in | Import from Confluence and others | Import from Notion and others | **Confluence (with attachments) and Notion** |
| SSO | SAML/OIDC | Atlassian Access | **OIDC native**; SAML via trusted proxy header |
| Presentations | Present mode, static `.pptx` | Doc-to-deck | `::deck` blocks with IDs, presenter, PaperDOM canvas, native `.pptx` with a fidelity report |
| Freedom beyond Markdown | HTML blocks (unstructured islands) | Macros | Typed directives + style tokens + component kits + sandboxed widgets |
| Databases / typed collections | ✅ core feature | ✅ maturing | 🟡 `::dataset` + page properties + `::page-properties` (non-goal: a full database clone) |
| Whiteboards | ❌ | ✅ | 🟡 `::canvas` (non-goal: a whiteboard clone) |
| Native mobile apps | ✅ | ✅ | 🟡 installable PWA |
| Marketplace | ✅ | ✅ | ❌ non-goal |

## 5. What is still missing

Ordered by how much each item would matter in an enterprise evaluation.

| # | Gap | Why it matters | Suggested approach |
|---|---|---|---|
| 1 | **Multi-node collaboration fan-out** | Horizontal scale; today multi-node deployments need sticky routing per document | A Redis or Postgres `LISTEN/NOTIFY` pub/sub behind the Yjs relay, keeping persist-before-ack |
| 2 | **Same-block concurrent edits** | Two people editing one paragraph keep both versions | Character-level Yjs text inside a block, reconciled back to the block's source span |
| 3 | **Native SAML** | Some IdPs are SAML-only | SAML SP with signed assertions, or keep the documented trusted-proxy path |
| 4 | **Embedding score calibration** | Duplicate detection and abstention thresholds were tuned for hash vectors | An eval set in `rag_evaluation`, and re-tuned thresholds per provider |
| 5 | **Database views over pages** | Notion's database views are its signature feature | Board, table, and calendar *views* over page properties with `::page-properties`. The source stays `.noma`, with no separate database store |
| 6 | **Instance-role S3 credentials, and blob migration between drivers** | Operating on AWS without static keys | A credential provider chain (IMDSv2 and web identity) and a `noma cloud migrate-blobs` command |
| 7 | **OIDC logout, group sync, and multiple IdPs** | Enterprise identity depth | RP-initiated logout, and group claims mapped to Noma groups |
| 8 | **Real AWS/EU deployment** | The CloudFormation template is validated but not deployed | One staging deployment with a smoke test |
| 9 | **Native mobile apps** | Field use | Keep the PWA; revisit after v1.0 |
| 10 | **v1.0 spec freeze and a second implementation** | "A format becomes a standard when someone else can implement it" (PLAN §25) | Grow `packages/noma-py-seed` to full conformance |

Explicit non-goals stay as `docs/direction.noma` states them: a plugin marketplace, a CSS theming engine, feature-for-feature clones of whiteboards and databases, and any path that is not reviewable as `.noma` source.
